# Tool selection on demand

Select capabilities only for a concrete task and explicit project need. Existing
tools are candidates, not a default installation list. Compare actual benefit,
context and elapsed-time cost, integration, controllability and maintenance cost.
Reuse working project capabilities before adding overlapping ones. Observe real
client loading, query behavior and failure boundaries; configuration alone is not
proof of availability or savings.

Cover the relevant dimensions: exploration, code understanding, project knowledge
retrieval, requirements/solution expression, UI design/prototyping, runtime/debugging/
acceptance, and databases. Record the user's selection before writing usage rules
or a necessary adapter. No guide installs, connects or configures tools.
