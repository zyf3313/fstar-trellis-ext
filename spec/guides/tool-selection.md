# Tool selection on demand

The selected uses are CodeGraph for code structure, QMD for document discovery,
GitHub/gh for repository research, Exa for supplemental Web coverage, DBHub for
optional database access, and `emil-design-eng` as the single UI design core.
These are scenario choices, not a universal installation or activation list.
Requirements use native Trellis discussion/tasks and
[Chinese PRD/TDD templates on demand](product-technical-design.md); runtime
acceptance reuses project commands, logs and applicable browser/device checks.
Unselected capabilities remain project-specific choices.

Read only the relevant scenario guide: [code](code-search.md),
[knowledge](knowledge-search.md), [UI](ui-design.md),
[database](database-access.md) or [Web/GitHub](web-research.md).
The project's workflow, existing index and local rules remain authoritative;
reference guides from that index or task JSONL as needed. No extra workflow or Skill
wrapper is required. No guide installs, connects or configures tools.

Record selected purpose separately from installed/discoverable, actually loaded,
and task-tested states in the project's evidence. Configuration alone proves none
of those runtime claims. Reuse existing capabilities; compare benefit, context and
elapsed time, integration, controllability and maintenance before adding overlap.
Missing tools use the guide's fallback or a reported gap; installation, models,
authentication and connections need an explicit integration scope. Preserve existing
machine installations and user model choices.
