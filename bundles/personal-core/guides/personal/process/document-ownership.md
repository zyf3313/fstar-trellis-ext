# Authoritative design documents

**Trigger:** Create or reference product/technical/UI content.

Discover existing authoritative directories first. New projects may use docs/product, docs/technical and design/ui. PRD covers project background, business panorama, module responsibilities and per-function flows/rules/acceptance. TDD means Technical Design Document: use the supplied twelve-chapter template, explain each function's mechanism/contracts/state/errors/recovery/compatibility/verification and choose a relevant diagram. UI specifies global language/shell and feature interactions. Trellis task artifacts retain task responsibilities and link IDs, versions and chapters; do not maintain a second full PRD/TDD/UI body.
