# QMD routing

**Trigger:** Locate a norm or design decision.

Index current rules and valid product/technical/UI design; archives are a separate optional scope. Search narrowly and inspect the authoritative hit with state/version/location. Required foundational originals remain mandatory. Refresh changed documents and rebuild affected vectors when model changes. Verify English rule and Chinese design/question recall. Distinguish keyword/vector/rerank readiness; missing models are a recorded gap. Disable collection update shell hooks. QMD searches acquired local documents; online stack discovery is a separate bootstrap step.

For CLI and MCP, set the child process `PWD`, `QMD_CONFIG_DIR`, and `INDEX_PATH` to the selected project. Verify the actual index path before reporting readiness; inherited `PWD` can create an index in the parent repository even when subprocess `cwd` is correct. Never reuse another project's index as evidence for the current project.

QMD 2.8.3 resolves `models.embed` in the index configuration before `QMD_EMBED_MODEL`. Audit existing collection ownership/hooks before changing models, use the package's YAML reader/writer, and approve only the reviewed configuration. Keep its model cache local. `qmd embed` can exit zero after skipping a busy index; readiness requires actual indexed vectors and a representative semantic hit. Bound endpoint checks as subprocesses because socket timeouts do not bound DNS/redirects. Unavailable downloads leave keyword/MCP readiness separate from semantic readiness; report the gap and retain a usable fallback.
