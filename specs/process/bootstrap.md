# Project initialization

For acquisition signatures, version boundaries and fallback states, read [stack sourcing](stack-sourcing.md). Use `personal.py query-stacks` before asset adoption; installation also runs this resolution. Default assets and identification report project-spec-review-required; explicit source acquisition remains separate from completed project adaptation.

**Trigger:** New project or first personal-library adoption.

Read current project rules first. For existing code, detect language/framework/version, package/layer, build/test and persistence from real manifests/lockfiles and focused source. For blank projects discuss and declare intended stacks before guessing. The personal library has no stack coding rules or default official fallback. Distill project rules from existing constraints, actual source and confirmed architecture; explicit --stack-registry candidates retain source/ref/hash/version and require review. Install compatible missing CodeGraph/RTK/QMD, configure the current client, index the project and actually verify calls. Enable one compatible database MCP only when the project uses a database. Installation/configuration/indexing/verification are separate states. Repeated runs repair gaps; upgrades preserve local changes and rollback. Do not change the application's runtime/dependencies to accommodate helper tools.

For external exploration, follow [routing and evidence budgets](../tools/exploration/usage.md): explicit source/provider constraints first, then reuse available capabilities and valid evidence, then fill only selected gaps. Load provider guidance/configuration/schema only for selected capabilities. Unrequested special sources are `selection_state=not_requested`; selected missing authentication is `pending`. Completion covers the selected scope; an explicit all-four request includes all four. Asset installation alone does not install research servers or prove client loading.

UI projects also install/reuse Impeccable and UI UX Pro Max; read the UI design tools rule. Default `tools.py` selects them from the actual UI stack or installed `ui` capability; `--ui` declares a blank UI project. Runtime installation, source files, real search/detection, client loading and optional hooks are separate evidence. Preserve existing provider files and hook configuration.

The library-root `STACKS.zh-CN.md` identification overview and `personal.py list-stacks` enumerate the full library. Detection uses reviewed `stack-definitions.json` markers, bounded structured manifests and recorded diagnostics. Identification does not supply coding rules, resolve unknown versions or certify runtime behavior. A detected/declared UI profile loads interface/tool guidelines; MongoDB/Redis require a separately chosen compatible provider. Do not execute discovered scripts or silently change dispatch configuration.
