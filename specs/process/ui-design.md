# UI before implementation

**Trigger:** Task has user-visible interaction.

A new UI project first confirms design language/tokens/components, overall shell/navigation, screen adaptation and key paths. Later features reuse that baseline and confirm affected pages/states/events/forms/feedback/navigation/recovery before implementation. Pure backend/CLI/infrastructure tasks record UI not applicable. Organize module → feature → page/state, with stable IDs linking PRD/TDD/acceptance. Provide editable source and an independent, extensible local preview scaffold with state galleries, runnable interactions and target-stack reference. Deliver a real, structurally validated exchange file and manual Figma/MasterGo import instructions. Do not upload it for the user unless explicitly requested. Record platform feedback separately; local file checks do not prove a lossless platform import.

Use compatible design skills by the current planning, prototype or review need; `personal-design` maintains the provider selection reference. Existing project baselines remain authoritative. Provider recommendations or context files do not create another independent product/design source, authorize immediate application development, or prove a UI has passed acceptance.
