# 需求管理：UI 设计技能应用示例

> 状态：可运行示例，视觉基线待用户评审 · 设计版本：v1.2 · 日期：2026-10-13

本轮沿用需求工作台的青绿色、中文系统字体和侧栏布局，演示设计资料查询、体验评审、改进和交付同步。没有增加真实业务后台或替其他项目确定风格。

## 两个技能如何分工

| 阶段 | 使用方式 | 实际结果 |
|---|---|---|
| 资料查询 | UI UX Pro Max 2.15.0：查询列表、提交反馈及 Vue 表单建议 | 读到移动表格呈现与提交状态建议；只采用符合现有范围的部分，不加入批量操作或新表单依赖 |
| 体验评审 | 主会话读取 Impeccable 4.5.2 的规划/打磨指导，并查看现有页面与状态 | 将工作台定位为完成任务的界面，保留已有身份，收拢搜索与列表层次，改善状态识别和窄屏阅读 |
| 机械检测 | 实际运行 Impeccable 引擎 0.1.14 的源码扫描 | 首次发现引用块样式及设计投影漏记的 token/字号；修正后当前扫描 0 项发现 |
| 交付同步 | 设计源 → 文档/token/画板/.sketch → 预览工程 | 同版 v1.2，生成的 PRODUCT.md/DESIGN.md 为受控投影，不能独立改成另一套来源 |

评审按当前项目的 inline 规则由主会话直接执行。未执行上游 `critique` 要求的双代理评审流程；因此本例不宣称完成该命令的完整双代理验收。`shape` 是 AI skill 的设计工作方式，不是让 CLI 自动生成最终页面的子命令。

## 可以直接看到的变化

- 搜索字段有可见标签，搜索、计数和记录属于同一个列表区域。
- 待讨论、设计中、待评审、实施中有不同语义色，并保留文字，颜色不成为唯一依据。
- 复查小字号文字对比度后，加深辅助文字和主色背景上的文字，主操作品牌色保持原值。
- 桌面行显示标题、编号和说明摘要；窄屏改为条目，直接读取内容，不用横向拖动表格。
- 本地原型提示降低视觉权重；重置演示数据移到辅助操作区域。
- 新建、首错聚焦、提交中禁用、失败保留输入、恢复重试、取消和详情返回保持原有合同。

在菜单中打开“需求管理 → 浏览需求”，可以搜索、进入详情并切换状态；“新建需求”可以操作表单和失败恢复。样式仍是本例草稿，后续项目必须先确认自己的设计语言。

## 当前检查

类型检查、生产构建、预览同步保护测试及设计文件 schema/中文回读/复现检查已通过。浏览器已检查搜索、空状态、详情、失败恢复、权限演示、首错焦点、提交失败后重试仅新增一条和取消不创建。

实际浏览器布局覆盖 320、375、390、430、1366、1920 CSS 像素；每次比较实际 clientWidth 与 scrollWidth，页面没有横向溢出。窄屏只展示条目，宽屏只展示表格。窄屏还验证了键盘进入详情与表单首错焦点。

源码扫描 0 项发现仅说明该扫描范围未命中规则，不等同完整可访问性、业务权限、性能或用户接受验收。没有连接真实业务数据库；Figma/MasterGo 的文件继续由用户手动导入，平台反馈单列。

## 后续项目怎么复用

初始化识别 UI 栈或显式声明 UI，缺少时安装这两个固定版本技能；已有兼容版本复用。本地修改不被覆盖，升级会生成候选并保留恢复前镜像。新项目先查风格与确定设计语言/框架，功能先定交互，原型评审通过并获得用户确认后再开发。

已安装技能可在后续回合被客户端发现；本例已按原文显式使用并验证 CLI，自动选中与自动 hook 状态分别记录。目前使用显式检测，未启用自动 hook。
